> 这是一次从境外直接访问的体检：命令和浏览器都在我们自购的搬瓦工洛杉矶 VPS（出口 IP 176.122.x.x，已打码）上运行，直接访问 RFKEY 源站。中间没有加 CDN，也没有做任何中转或线路优化。报告只说明“美国加州的访客当时打开这个站是什么样”。结论只适用于这一次的单一测试点、公开页面样本，不代表全站交易流程或全球用户体验已通过验收。

## 报告摘要

本次在美国加州 VPS 上直接测试 RFKEY 商城。5 个公开页面的 15 次 HTTPS 传输及 25 次浏览器主导航均返回 HTTP 200，页面具有实际内容。主要问题是首页冷加载的剩余资源耗时偏长、英文版本内容不完整且金额译文不一致，以及 HTTP 入口未自动升级到 HTTPS。

## 体检发现与优化建议

- **公开页面可从本次境外测试机访问，桌面和手机仿真均显示实际内容**：15 次 curl 请求全部状态 200、退出码 0、TLS 证书校验成功；25 次浏览器主文档状态均为 200。主测记录的 1,242 条浏览器响应均为 200，观测窗口内未记录网络失败、HTTP 错误、控制台错误或脚本异常。商品详情页实际展示了型号、价格、库存和资料入口；登录页展示登录与验证组件。另有 1 次加载等待超时，已在下方单列，不能概括为零异常。
- **优先优化首页冷加载：主要内容先出现，但完整资源加载存在明显拖尾**：中文首页桌面冷加载 LCP 候选中位数为 2.156 秒，范围 2.044–5.204 秒；load 事件中位数为 12.171 秒，范围 10.110–19.098 秒。第 3 次冷加载触发 15 秒 load 等待超时，随后采样已为 complete，loadEventEnd 为 19.098 秒。热加载 LCP 中位数为 1.004 秒，load 中位数为 1.289 秒；每次热加载记录到 70 条磁盘缓存响应。冷加载可计量资源传输体积约 14.374 MB，跨域缺少时序授权的资源可能未被完整计量。补测发现轮播图 3.png 约 1.865 MB、2.png 约 1.251 MB，图片是值得优先优化的具体目标；单次补测不能证明全部延迟均由图片体积造成。**建议**：先压缩和按展示尺寸提供轮播图、产品图，调整非首屏资源加载，再用相同境外测试机和相同样本复测。不要把 load 时间描述成用户在此之前完全看不到页面。
- **英文页可以打开，但需要校对金额并补齐图片内文字**：英文首页存在英文导航和正文，确认语言切换有效。中文首页顶部促销门槛为 5,000 元，英文顶部出现“50 million yuan”，而同一英文页另一处仍写 5,000 元，金额明显不一致。英文页面截图中的宣传横幅、四张宣传卡片及部分分区标题仍为中文；本次已采样页面的 html language 属性为空。**建议**：由商家确认促销原意后修正金额，校对英文文案及图片内文字，并正确设置页面语言属性。当前结果不能代表全站翻译已完成。
- **HTTP 入口仍停留在 HTTP，需要统一跳转 HTTPS**：补充检查中，HTTPS 首页返回 302 并跳转到 HTTPS 页面，证书验证成功；HTTP 首页跟随 1 次 302 后最终仍停留在 HTTP 页面，返回 200。当前只能确认所测 HTTP 入口没有强制升级 HTTPS，未执行账号登录或密码提交。**建议**：在源站或接入层配置 HTTP 到 HTTPS 的301 重定向，并检查站内链接、静态资源和登录入口。
- **图片补查未发现真实地址加载失败，空地址元素不应误报为坏图**：对中文首页、分类页、详情页、英文首页分别进行滚动补查，均到达页面底部；有实际地址的图片加载失败数和待完成数均为 0。四页分别存在 17、45、7、17 个没有实际 src/currentSrc 的图片元素，滚动前后未变。这些空地址元素并未形成失败的图片网络请求；是否属于占位、装饰或缺失内容，需要结合源站模板逐项判断。原始主测中的 images.broken 包含这些元素，报告保留原始数据并以专项诊断纠正判读。

## 方法与局限

1. 本报告只代表指定美国加州机房测试机和此次测试时段，不代表全球所有国家、运营商、家庭宽带或真实手机网络。
2. 冷加载使用新浏览器上下文；系统 DNS、源站缓存及 CDN 缓存没有强制清空。热加载复用上下文并再次打开同一地址，实际缓存命中按浏览器记录。
3. 采用 Chromium 无头浏览器且不限制 CPU 或带宽。手机模式使用 iPhone 13 参数仿真，浏览器引擎仍是 Chromium，不是 Safari 或实体 iPhone。
4. LCP 只统计采样窗口内观察到的候选，CLS 也仅覆盖这个窗口；没有用户交互，因此没有测量真实用户 INP。报告不虚构性能评分或全站达标结论。
5. 服务器直接访问源站，未经过任何中转、URL 改写或资源拦截；源站脚本会正常运行，可能自动发送请求。本次没有点击按钮、填写表单、登录、购物、提交订单或付款。
6. 图片统计覆盖当时 DOM 中的 img 元素；原始 broken 字段代表 complete 且 naturalWidth 为 0 的元素，包含无真实地址的占位，不直接等同损坏图片。背景图、后续懒加载及其他路由仍可能存在未覆盖的问题。
7. HTTP 2xx/3xx 仅说明导航或传输返回成功；内容正确性、失败资源、脚本异常及完整交易流程需分别评估。
8. 测试工具放在独立临时目录，没有修改商家源站程序、DNS、账户或订单。报告与原始数据不含登录密码、Cookie 存储或请求体。
9. 若要给商家出具正式出海验收结论，还需根据目标市场增加测试点，并使用商家测试账号或支付沙箱验证业务流程。本报告未覆盖这些项目。

## 实测结论与建议

{{< advice n="1" prio="high" title="首页图片过大，完整加载中位约 12 秒" >}}
**问题**：中文首页桌面冷加载 load 中位数 12.171 秒（范围 10.110–19.098 秒），但主要内容 LCP 中位 2.156 秒就已出现，说明拖慢的是后续资源。冷加载可计量资源约 14.374 MB，其中轮播图 3.png 约 1.865 MB、2.png 约 1.251 MB。

**做法**：轮播图和产品图转 WebP/AVIF，按实际显示尺寸输出；非首屏图片懒加载；静态资源开启浏览器缓存和压缩；有条件可再用 CDN 分发图片等静态资源。

**说明**：瓶颈在资源体积，单纯升级服务器配置解决不了这一项，所以建议先做这一项。具体能快多少，以优化后的复测数据为准。
{{< /advice >}}

{{< advice n="2" prio="high" title="HTTP 入口没有跳转到 HTTPS" >}}
**问题**：所测 HTTP 首页最终仍停留在 HTTP 页面。

**做法**：在源站或接入层配置 HTTP → HTTPS 的 301 跳转，并检查站内链接、静态资源和登录入口都使用 HTTPS。
{{< /advice >}}

{{< advice n="3" prio="mid" title="英文页金额与图片文字需要校对" >}}
**问题**：英文页顶部促销金额与中文页、同页另一处不一致；宣传横幅和卡片图片里仍是中文；页面 html lang 属性为空。

**做法**：确认促销原意后修正英文金额，补做英文版宣传图，并给中英文页面分别设置正确的 lang 属性。
{{< /advice >}}
